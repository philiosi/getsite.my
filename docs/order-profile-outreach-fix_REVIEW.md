# 주문 저장 복구 + 스테이라·OLC 신청 연결 (2026-11-20)

요청서: `claude-request-sample-param-fix.md` (Juno, 기준 커밋 88cd575)와 사용자의 점검 요청. 상태: 규칙, Apps Script, getsite-my, getsite-samples를 모두 배포했고 운영에서 테스트 주문 1건(WO-2026-7337)으로 확인했다.

## 발견한 문제

1. **모든 주문이 저장되지 않았다.** 88cd575(선택 입력 추가)가 주문 문서 최상위와 `brief` 바로 아래에 `profile`을 넣었는데, `firestore.rules`는 두 곳 모두 키 목록을 정확히 검사한다. 규칙은 바뀌지 않은 채 화면만 배포돼(2026-11-18 0시경 KST), 어떤 샘플로 신청하든 마지막 제출이 `permission-denied`로 거부됐다. 운영 DB의 마지막 주문은 11월 9일이라 그사이 실패한 고객 수는 알 수 없다.
2. **스테이라 요가·OLC 커피 버튼에 `?sample=`이 없었다.** 등록부(`outreach.json`)와 규칙 허용 목록에도 두 ID가 없었다. 기존 4개는 정상이었다.
3. **접수 메일·제작 요약에 선택 입력이 없었다.** `brief-sync.gs`가 `profile`을 읽지 않았고, 홍보 샘플은 메일에 이름 대신 ID 문자열이 나갔다.

요청서와 달리 한 점: "다른 파일 수정 금지"였지만 1번 문제를 풀려면 `order.js`를, 메일 표시를 위해 `brief-sync.gs`를 고쳐야 했다. 사용자 승인을 받았다. 규칙은 요청서대로 ID 2개만 추가했다.

## 규칙 한도에 대해 (측정)

`firestore.rules`는 표현식 1000개 한도 바로 아래에 있다. 에뮬레이터에서 실제 스토어로 만든 주문으로 측정했다.

- 섹션 11개 이하: 참고 링크 3개까지 모두 저장된다.
- **섹션 12개 이상 + 참고 링크 3개: 거부된다.** 88cd575, 운영(수정 전), 수정 후 규칙에서 경계가 똑같다. 이번 변경과 무관한 기존 문제다.
- 선택 입력(문자열 1개)과 허용 ID 추가는 이 경계를 바꾸지 않는다.
- `profile`을 규칙에서 직접 검사하는 후보 3개는 한도를 넘었다. 단, 그 시험 문서는 링크 3개짜리라 위 기존 문제와 겹친다. "규칙에 넣을 수 없다"는 것까지 증명한 것은 아니다.

## 검증

- 로컬: `node --test` 55개 통과 (v5 unit, v4 backend, v3 unit, ref-upload).
- 에뮬레이터: `tests/v5/rules.test.mjs` 10개 통과. 실제 `buildOrder` 문서로 홍보 6개·vanilla·artist 주문이 선택 입력 유무와 관계없이 저장됨.
- 배포 전 대조: Apps Script 원격은 `brief-sync` 19줄만 달랐고, 홍보 샘플 사이트는 18개 파일 중 16개가 운영과 같고 2개가 버튼 한 줄만 달랐다.
- 운영: 홍보 페이지 6개의 버튼 → 신청 2단계 진입(샘플 선택, 이름·목적·섹션 채움, 안내 토스트)을 데스크톱 6개 + 모바일 2개로 확인. 저장은 가짜로 바꿔 문서 형태만 확인.
- 운영 테스트 주문: 스테이라 요가 버튼에서 시작해 실제 화면으로 제출. WO-2026-7337, 사이트 이름 `[테스트] 스테이라 요가`, 이메일은 운영 계정. 저장된 문서에 최상위 `profile` 없음, `references.profile`은 문자열.

## 남은 것

1. **섹션 12개 이상 + 참고 링크 3개 주문이 거부된다** (기존 문제). 고치려면 규칙의 표현식을 줄이는 재구성이 필요하다.
2. 선택 입력은 서버에서 길이를 검사하지 않는다(화면과 Apps Script에서만 자른다). 1번을 풀 때 함께 볼 수 있다.
3. 홍보 샘플 주문은 메일의 "작품 세트"가 빈칸이다(`concept`을 주문에 싣지 않음). 11월 15일 기록에도 있던 항목이다.
4. 테스트 주문 WO-2026-7337은 운영 DB에 남아 있다. 지울지는 사용자 결정.
5. 샘플 페이지를 아티팩트에서 다시 export하면 버튼이 옛 주소로 돌아간다. export 뒤 주소를 다시 고쳐야 한다.
6. 스테이라 등록부의 팔레트 `#9A7B8C`는 실제 페이지에 없는 색이다(설명용 값, 동작 영향 없음).

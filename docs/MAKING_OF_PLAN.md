# "제작 과정 들여다보기" 페이지 배치 계획

대상 파일: `~/Downloads/daol_sample_jaejak.html` (다올 그림 스튜디오, WO-2026-6934 제작 과정 안내)
작성일: 2026-11-10. 상태: 계획만. 구현·배포 전.

## 1. 지금 있는 안내 세 가지 (확인한 사실)

| 이름 | 위치 | 하는 일 | 들어오는 길 |
|---|---|---|---|
| 제작 과정, 다섯 단계 | 메인 `/#process` | 주문 마법사 자체 (샘플 고르기 → 구성 → 견적 → 접수) | 상단 메뉴 "제작 과정", 첫 화면 버튼 |
| 주문 진행 안내 | `/order-guide/` | 접수 뒤 7단계의 절차: 메일 2통, 전체 의뢰 코드, Drive 올리기, 결제. 메일 샘플 2개 포함 | 접수 완료 화면의 링크 하나뿐 |
| (새) 제작 과정 안내 | 아직 없음 | 주문 한 건이 샘플이 되기까지의 판단 과정 | 없음 |

새 파일의 구성 (6장, 데스크톱 높이 약 12,000px, 휴대폰 약 18,900px, 1.9MB, 이미지 3장 내장):

1. 01 주문 접수: 주문서 한 장 정리
2. 02 요구사항 분석: 요청 → 정리·해석 → 디자인 반영 표 5개
3. 03 레퍼런스 분석: 참고 슬라이드에서 읽은 규칙 7가지, "베끼지 않고 새로 그린다"
4. 04 아직 반영하지 못한 것: 빈 자리 4곳과 이유
5. 05 샘플 완성 이후: 7단계 표, 결제, 메일
6. 06 주문 전에 준비하면 좋은 것 8가지

## 2. 역할 구분

- **주문 진행 안내 = 절차.** "언제 무슨 메일이 오고 내가 뭘 해야 하나." 주문한 뒤에 읽는다. 모든 주문에 똑같이 맞는다.
- **제작 과정 들여다보기 = 판단과 품질의 증거.** "내 요청이 어떻게 읽히고 디자인이 되나, 참고 이미지는 어떻게 쓰이나, 없는 정보는 어떻게 하나." 주문하기 전에 믿음을 주고, 샘플을 받은 뒤에는 확인표가 된다. 사례 한 건을 깊게 본다.

겹치는 부분은 05장(7단계·결제)과 06장 일부(자료 준비)뿐이다. 01~04장은 기존 안내 어디에도 없는 내용이다.

## 3. 하나로 합칠까: 합치지 않는다 (추천)

- 읽는 시점이 다르다. 진행 안내는 접수 뒤, 들여다보기는 접수 전과 샘플 확인 때.
- 길이. 합치면 휴대폰에서 3만px 가까이 된다.
- 들여다보기는 다올 샘플의 색·서체로 입혀져 있고, 그 자체가 "레퍼런스가 규칙이 된다"는 증거다. 진행 안내의 중립적인 모양에 넣으면 그 효과가 사라진다.
- 대신 **겹치는 내용은 한쪽만 원본으로 둔다.** 7단계와 결제는 진행 안내가 원본. 들여다보기 05장은 7단계 줄 하나와 "자세한 절차는 주문 진행 안내에서" 링크로 줄인다. 결제 문구가 두 곳에서 따로 바뀌는 일을 막는다.

대안 비교:

| 안 | 내용 | 평가 |
|---|---|---|
| A. 별도 페이지 + 서로 연결 (추천) | `/making-of/`로 올리고 양쪽에서 링크 | 역할이 분명, 고칠 것이 적음 |
| B. 진행 안내 안에 탭이나 장으로 합침 | 한 주소 | 너무 길고 모양이 충돌, 다시 만들어야 함 |
| C. 메인 페이지 섹션으로 요약만 | 표 1~2개만 발췌 | 가볍지만 핵심인 깊이가 사라짐. A에 더해 "맛보기"로는 가능 |

## 4. 어디에 붙일까 (들어오는 길)

우선순위 순.

1. **메인 `#process` 머리말 옆 (주 입구).** "제작 과정, 다섯 단계" 설명 아래에 한 줄 카드: "제작 과정 들여다보기: 주문 한 건이 샘플이 되기까지 ↗". 주문을 망설이는 사람이 보는 자리.
2. **3단계 참고 사이트·이미지 칸 도움말.** "참고 자료가 어떻게 쓰이는지 보기 ↗" → `/making-of/#reference`. 참고 자료를 붙이는 바로 그 순간의 궁금증에 답한다.
3. **주문 진행 안내 3·4·5단계.** 3단계(브리프 정리) → `#requirements`, 4단계(샘플 제작) → `#reference`, 5단계(샘플 완료 메일) → `#notyet`. "이 단계에서 실제로 하는 일 보기".
4. **자주 묻는 질문.** "참고 이미지를 그대로 쓰나요?", "자료가 없으면 어떻게 되나요?" 답 끝에 링크.
5. **접수 완료 화면.** 지금의 "주문 후 진행 과정 보기" 아래에 둘째 링크.
6. (나중) 접수 안내 메일의 "다음 단계" 문단. Apps Script를 바꿔야 해서 2차로 미룬다.

상단 메뉴에는 넣지 않는다. 메뉴의 "제작 과정"이 이미 주문 마법사를 가리켜 이름이 헷갈린다.

## 5. 올리기 전에 고칠 것 (파일 내용)

지금 글은 "다올 주문자 본인"에게 말하는 글이다. 공개 사례로 쓰려면 다음을 고친다.

1. **읽는 사람.** "주문자는 자기 주문이 어디까지 왔는지 이 페이지에서 따라갈 수 있습니다" → "주문하시면 같은 과정을 거칩니다" 식으로.
2. **멈춘 상태.** "지금 4단계까지 완료, 5단계 발송 대기 중" → 사례 설명으로. 진행 안내에는 이미 다올의 샘플 완료 메일 예시가 있어 서로 어긋난다.
3. **지킬 수 없는 약속.** 맨 아래 "주문자의 주문도 같은 방식으로 정리해서 안내합니다"는 주문마다 이런 페이지를 만든다는 뜻으로 읽힌다. "같은 내용(요청 → 해석 → 반영, 반영 못 한 것)이 샘플 완료 메일에 담깁니다"로 바꾼다. 이것은 실제로 하고 있는 일이다.
4. **"실제 주문 사례" 표기.** 다올이 실제 고객 주문인지 예시 주문인지에 따라 "예시 주문"으로 바꾼다. 진행 안내는 "예시 주문"이라고 쓰고 있다. **사용자 확인 필요.**
5. **"이 안내 페이지에는 샘플 링크를 걸어 두지 않았습니다".** 공개 사례라면 오히려 "완성된 샘플 보기" 버튼이 있어야 설득력이 있다. 진행 안내의 메일 샘플이 이미 그 샘플로 연결된다. **사용자 확인 필요.**
6. **05장 줄이기** (3번 항목).
7. **나가는 길 추가.** 지금은 링크가 하나도 없다. 머리말에 getsite.my로 돌아가기, 끝에 "샘플 받기"(`/#process`)와 "주문 후 진행 안내"(`/order-guide/`).
8. **결제 문구 맞추기.** 진행 안내의 "VAT 별도", "계약금/착수금" 용어와 같게.

## 6. 기술 작업

- 주소: `/making-of/` (`scripts/v4-build.mjs`가 `public/making-of/`로 복사, 원본은 `v5/making-of/index.html`).
- 내장 이미지 3장은 파일로 빼서 늦게 불러오기(첫 화면 1장 제외). 1.9MB 한 덩어리 → HTML은 수십 KB.
- 제목·설명·공유 이미지(og) 넣기. 제목 "제작 과정 들여다보기 — getsite.my".
- 테스트(e2e에 추가): 페이지가 열림, 6개 장 id, 옆 스크롤 없음(1440/375), 나가는 링크 3개, 메인·진행 안내·3단계 도움말의 들어오는 링크가 맞는 장으로 감, 어두운 화면에서 글자 대비.
- 순서: 미리보기 채널 → 사용자 확인 → 운영 배포 → 커밋.

## 7. 사용자가 정할 것

1. 다올은 실제 주문인가, 예시 주문인가 (표기).
2. 완성된 다올 샘플로 가는 버튼을 넣을까.
3. 메뉴 이름: "제작 과정 들여다보기" 그대로 쓸까.
4. 메인 페이지에 맛보기(요청 → 해석 → 반영 표 1개)를 넣을까, 링크 카드만 둘까.

## 8. 위험

- 이름 혼동: "제작 과정"(마법사), "제작 과정 들여다보기", "주문 진행 안내" 세 가지. 링크 문구에 항상 한 줄 설명을 붙인다.
- 단계 수 혼동: 마법사 5단계, 진행 7단계, 들여다보기 6장. 들여다보기의 번호는 "장"으로 읽히게 하고 7단계 표는 진행 안내에만 둔다.
- 사례가 일러스트 포트폴리오 한 건뿐이라 가게·기업 주문자에게는 덜 와닿는다. 나중에 다른 업종 사례를 추가할 수 있게 주소를 `/making-of/daol/`로 둘지 검토.

## 9. 검토 반영 (EGM 검토 2건, 2026-11-10) — 위 내용보다 이 절이 우선

검토자: 범위·단순성(zoom-out), 처음 보는 독자(comprehension). 지적은 코드와 글에서 직접 확인했다.

**먼저 정해야 진행할 수 있는 것 (5절 4·5번을 앞으로 옮김)**
- 다올이 실제 고객 주문이면: 동의를 받고 의뢰번호를 지운 뒤에만 공개. 예시 주문이면 "예시 주문"으로 표기.
- 완성 샘플 링크를 넣을지.

**들어오는 길은 2개로 시작 (4절 축소)**
1. 메인 `#process` 머리말의 링크 카드 (주문 전).
2. 주문 진행 안내 4단계(샘플 제작)의 링크 하나 (주문 후).
- 뺀 것: 접수 완료 화면 링크(기존 테스트가 "안내 링크는 하나"를 확인하고, 믿음을 주는 글을 읽을 시점도 아님), 자주 묻는 질문(해당 질문이 지금 없어 새 글을 써야 함), 3단계 도움말, 장별 깊은 링크 3개, 메일. 필요해지면 그때 추가.

**글에서 추가로 고칠 것 (5절에 더함)**
- 번호 충돌: 들여다보기가 자기 장을 "02단계", "04단계"라고 부른다. 진행 안내의 4단계(샘플 제작)와 헷갈리므로 "02장", "04장"으로.
- 샘플이 오는 메일: "주문 접수 후 발송되는 메일"은 접수 안내 메일로 읽힌다. "샘플 제작 완료 메일(5단계)"로.
- 잔금 시점이 서로 다름: 진행 안내 "잔금이 확인되면 배포·인계", 들여다보기 "인계할 때 잔금 정산". 진행 안내에 맞춘다.
- 진행 안내 자체도 "착수금"과 "계약금"을 섞어 쓴다(1곳). 같이 고친다.
- 견적 500,000원에 VAT 표기 없음. 진행 안내의 "VAT 별도"와 맞춘다.
- "샘플 확인 전에는 어떤 비용도 청구하지 않습니다"는 들여다보기에만 있다. 사실이면 진행 안내에도 넣고, 아니면 뺀다. **사용자 확인 필요.**
- 자료 보내는 곳: Drive 폴더라고 한 줄 적는다.

**기술 작업 정정 (6절)**
- 빌드 스크립트는 `v5/`를 통째로 복사하므로 고칠 필요 없음. `v5/making-of/`에 두면 된다.
- 테스트는 3개만: 페이지가 열림, 옆 스크롤 없음(1440/375), 나가는 링크가 맞음. 여기에 들어오는 링크 2개 확인.
- 내장 이미지 3장을 파일로 빼는 일은 유지.
- 주소는 `/making-of/`. 메인 페이지 맛보기와 `/making-of/daol/`은 하지 않는다.

**이름**
- "제작 과정"이 세 군데서 쓰여 헷갈린다. 링크 문구 후보: "제작 사례 보기: 다올 그림 스튜디오" (검토 제안) 또는 "제작 과정 들여다보기" (사용자 원안). 사용자가 정한다.

## 3회차: 작품 크게 보기 (갤러리 11종 + 배포 페이지 임베드)
요청: 작품을 누르면 나머지는 흐려지고 선택한 작품이 커지며, 그 상태에서 좌우로 넘겨 보기. 갤러리마다 적용.

**만든 것**
- `v3/gallery/viewer.js`, `viewer.css`: 공용 뷰어. 누른 작품의 박스에서 커져 화면 가운데로 온다.
  - 넘기기: 좌우 끌기(속도 유지), 화살표 버튼, 방향키, 가로 휠.
  - 닫기: 닫기 버튼, Esc, 아래로 끌기, 사진 옆 탭, 세로 휠.
- `engine.js`가 모든 레이아웃에 `view(id)`를 넘긴다.
  - 11개 레이아웃이 탭과 Enter/Space로 뷰어를 연다.
  - 기존 masonry/grid 확장 카드와 museum 확대는 뷰어로 대체했다.
  - focus, strip, timeline, coverflow는 첫 탭에 가운데로 가져오고, 다음 탭에 연다.
- 배포 페이지용 임베드(`v3/embed/`)도 같은 뷰어를 쓴다. 열린 동안 휠은 페이지를 스크롤하지 않는다.

**테스트**
- e2e 52/52, 단위 24/24.
- 실제 마우스 입력으로 11개 레이아웃 × 1440/375px을 검사했다: 열기, 끌어 넘기기, 아래로 끌어 닫기, 사진 옆 탭 닫기, 원래 자리 복원, 페이지 유지.
- 배포 페이지 임베드는 12개 칩 × 1440/375px을 검사했다(스크래치패드 스크립트).
- 새 회귀 테스트는 결함을 주입해서 실패하는 것을 확인했다.

| index 미리보기가 마우스 사용 시 남음, flow 클립과 크기 차이 | Argon | 보류 | 흐린 배경 안이라 영향이 작음 |

| 2차(Codex, 수정분만): 닫은 뒤 휠 잠금이 남아 다시 연 뷰어가 휠을 무시함 | Codex | 확인 | teardown에서 휠 상태 초기화 |

리뷰어 상태: Codex 정상(3건, 2차 2건), Gemini 정상(1건, 스킬 충돌 경고만 출력), Argon(agy) 정상(10건), ECC typescript-reviewer(8건), a11y-architect(8건).

## 남은 위험
- 리뷰는 2회차까지. 2회차 수정분(제스처 `lead`, 고무줄 복원, 키보드)은 다시 리뷰하지 않았고 브라우저 검사와 전체 테스트로만 확인했다.
- 갤러리 레이아웃별 키보드 조작은 작품마다 Tab과 Enter로 크게 보기까지 구현했다. 레이아웃 안에서 방향키로 작품을 옮기는 동작은 레이아웃마다 다르다.
- 크게 보기에서 실제 터치 기기의 스와이프와 포커스 복귀는 미검증이다(마우스 입력과 합성 이벤트로만 확인).
- 실제 터치 기기, 저사양 GPU에서의 유리 닦기 프레임은 미검증(헤드리스·실 GPU만).
- `scenes/*.js`와 `app.js`는 ECC 코드 리뷰가 끝나지 않음(Codex·Gemini는 `app.js` 포함 검토).
- 거품숲 비누 컷아웃 가장자리의 흰 테두리는 원본 이미지 문제.
- 운영 규칙이 아직 열려 있어 익명으로 주문 목록이 조회된다(아래 사용자 할 일 1).

## 사용자가 할 일
1. `v3/backend/firestore.rules` 검토 후 배포 승인. 배포하면 공개 목록이 막히고, 기존 4자리 주문 번호 방식(v2)은 새 주문을 못 만든다. 이미 노출된 주문 3건의 처리 결정.
2. Apps Script 프로젝트에 `brief-sync.gs`, `catalog-snapshot.gs`, `appsscript.json`을 넣고 `installTrigger` 1회 실행.
3. Muse에 Drive `getsite-orders` 폴더 읽기 권한만 부여.
4. `/v3/` 호스팅 반영. `firebase.json`이 저장소에 없는 `public/`을 가리키므로 배포 구조를 먼저 정해야 한다.
5. 결제 후 주문 `status`를 `결제 완료`로 바꾸면 고객 주문 페이지에 섹션 요청 폼이 열린다.

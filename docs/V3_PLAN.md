# getsite.my v3 계획

토론 참가: Claude(최종 결정), Codex, agy(Gemini 4 Argon), ECC architect, ECC security-reviewer.
작성일: 2026-11-06. 수치 중 측정하지 않은 것은 "미측정"으로 표시한다.

## 1. 한 줄 컨셉

**페이지 자체가 고객의 사이트다.** 첫 화면은 완성된 사이트이고, 아래 캡슐에서 고르면 그 자리에서 사이트가 바뀐다.

## 2. 기존의 문제

운영 페이지 한 장에 샘플, 5단계 설명, 긴 폼, 섹션 13종, 갤러리 11종, 구성안, 가격표, 계산기, FAQ 11개, 조회, 결제 후 입력, 관리자가 모두 들어 있다. 고객은 고르기 전에 읽어야 한다.

v3에서 뺀 것: 섹션 체크박스(결제 후로), 견적 계산기, 5단계 설명, 관리자 화면, 긴 FAQ.

## 3. 화면 흐름

1. **진입.** 화면 전체가 라이브 사이트. 상단에 얇은 한 줄(서비스 설명, "이미지와 문구는 샘플", 기본 50만 원·VAT 별도).
2. **고르기.** 하단 캡슐 하나: `컨셉` `첫 장면` `갤러리` + `이 구성으로 샘플 받기`. 칩을 누르면 그 칩에서 트레이가 자란다. 한 번에 하나만 열린다.
3. **즉시 반영.** 컨셉은 색·서체·사진을 바꾸고, 첫 장면은 재생되고, 갤러리는 무대가 갤러리로 이동하며 같은 작품이 새 배치로 날아간다.
4. **샘플 받기.** 캡슐에서 시트가 올라온다. 구성 한 줄 요약, 사이트 이름·이메일·한 줄·참고 링크(선택)·동의. 무대는 시트 뒤에 계속 보인다.
5. **접수 완료.** 의뢰번호와 전용 링크. 저장 성공과 자료 폴더 준비를 따로 표시한다.
6. **샘플 확인 후 결제.** 이메일로 안내(결제 연동은 범위 밖).
7. **결제 후.** `v3/order.html#t=키`에서 섹션별 요구사항 입력.

무대는 세 페이지다: 첫 장면 / 갤러리 / 마무리(소개·문의). 문서 스크롤을 쓰지 않고 view 전환이며, 다음 페이지 윗부분이 아래로 살짝 보인다.

## 5. 모션 수준을 올리는 방법

기존 샘플은 효과 하나씩이었다. v3 장면은 모두 **앵커 + 재질 + 묶음 + 직접 조작**을 갖춘다.

| 장면 | 기준점 | 내용 |
|---|---|---|
| 필름 | hansakim.com | 20초 4장면. 글자가 굵어지다 창이 됨. 재생·정지·타임코드·건너뛰기, 휠·드래그 스크럽 |
| 앵커 순환 | 누리마당 | 중앙 고정, 대형 단어·배경·전후경 오브젝트가 묶음으로 교체. 아치 틀, 잡아서 넘기기 |
| 김 서린 유리 | Condensation | WebGL 김, 포인터로 닦기, 다시 서림, 스퀴지로 걷힘 |
| 스택 & 펼침 | Stack & Fan | 쌓이고 기울며 펼쳐짐. 던지면 속도를 이어받아 넘어감 |

갤러리 11종은 모두 스프링 기반의 직접 조작(1:1 드래그, 관성 투영, 러버밴딩)을 갖는다.

## 6. 구조

번들러 없는 ES 모듈, 정적 배포.

```
v3/index.html    셸
v3/v3.css        토큰·크롬
v3/app.js        상태·무대·캡슐·트레이
v3/catalog.js    ID·토큰·작품·Muse용 스펙 (catalogVersion)
v3/core/         spring(단일 ticker, 닫힌 해), gesture(드래그·관성·러버밴드), state(URL 직렬화)
v3/scenes/       필름·앵커·유리·스택 (선택 시 lazy, destroy 강제)
v3/gallery/      engine(FLIP), layouts(11종)
v3/order/        sheet, brief(순수 함수), api(제출 시 Firebase lazy)
v3/order.html    결제 후 섹션별 입력
v3/backend/      firestore.rules 초안, Apps Script 동기화 스크립트 (미배포)
```

- 미니 사이트는 iframe이 아닌 같은 DOM(제스처·토큰·좌표 공유).
- 장면 계약: `mount(el, ctx) → {play, pause, seek, onWheel, destroy}`. 장면은 전역 스크롤을 읽지 않는다.
- 활성 장면 하나만 마운트. WebGL 실패·컨텍스트 소실·축소 모션이면 정지 화면으로 대체.

## 7. Muse 전달

```
브라우저 → Firestore orders/{128비트 키}  (원본, briefStatus: pending)
           └ Apps Script 시간 트리거(운영자 권한)가 pending을 읽어 Drive에 brief.json / brief.md 저장, 상태 갱신
```

- 공개 POST로 brief를 받지 않는다. 위조 brief로 Muse를 조종하는 경로를 막기 위함이다.
- 선택 항목은 enum ID만, `catalogVersion` 고정. 고객 자유 입력은 `customerText`에 길이 제한·제어문자 제거 후 분리.
- `brief.md`는 서버가 JSON에서 재생성하고, 고객 문구를 "신뢰할 수 없는 데이터" 블록에 넣는다.
- 전달 실패해도 접수는 유효하며, 전달 상태는 Firestore에 남아 재시도된다.

## 8. 보안

**실측:** 현재 비로그인으로 `orders` 목록 조회가 되어 주문 3건의 이메일·이름이 공개되어 있다. 운영 규칙은 사용자 승인 후 변경한다.

- 문서 ID: `WO-YYYY-NNNN-<20자 난수>`. 화면에는 앞부분만 표시.
- 전용 링크는 `#t=` 프래그먼트, `Referrer-Policy: no-referrer`, `noindex`.
- 사용자 입력은 `textContent`로만 렌더링, URL은 https만 허용.
- 한계: Firebase Auth 없는 구조라 키가 새면 해당 주문은 읽고 수정할 수 있다. 쓰기 스팸 방어는 App Check 도입 전까지 없다.

## 9. 수용 기준

1. 첫 화면에서 설명을 읽지 않아도 선택 후 결과가 바뀌는 것을 볼 수 있다.
2. 3×4×11 전 조합이 콘솔 오류 없이 렌더링된다.
3. 320·375·414·768·1440폭에서 가로 스크롤이 없고 캡슐이 한 줄이다.
4. 애니메이션 도중 다른 항목을 눌러도 튀지 않고 현재 위치에서 이어진다.
5. 드래그는 1:1이고 놓을 때 속도가 이어진다.
6. `prefers-reduced-motion`에서 움직임이 크로스페이드로 대체되고 모든 기능이 동작한다.
7. 저장 실패 시 "접수됨"으로 표시하지 않고 재시도를 제공한다. 중복 제출해도 주문이 하나다.
8. brief가 스키마를 통과하고, 고객 문구가 지시문 위치에 들어가지 않는다.
9. 테스트는 운영 Firebase에 쓰지 않는다.

- 운영자가 대표 조합 스크린샷(컨셉 3 × 기본 장면·갤러리)을 보고 승인한다.

- 컨셉 전환은 글꼴·이미지 준비 후 교체, 실패 시 화면 유지와 "불러오지 못했습니다. 다시 시도"
- 100dvh 무대, 414px 이하 CTA "샘플 받기", 시트 상단 선택 요약 고정
- 무대 안 링크는 inert, 살아 있는 CTA는 캡슐 하나
- 캡슐·트레이·상단 줄은 유리 대신 컨셉 종이색 불투명 면
- 오류 문구: 저장 실패, 잘못된 주문 링크, 오래된 URL 기본값 안내
- 선택지 이름은 전문용어 대신 쉬운 말(예: 메이슨리 → 벽돌처럼 쌓기)
